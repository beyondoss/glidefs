Run: 2026-05-13, host paraglide (16-core, single-NUMA, NVMe), 32 GB RAM
Kernel: 6.12.74+deb13+1-amd64
Branch: jared/memories
Build: with async-backpressure pool, FIFO waker queue, bulletproof
       per-page volatile pre-fault for NUMA-correct first-touch

==============================================================================
Structural changes since usercopy-pool-5k
==============================================================================

  1. acquire() returns an AcquireFut instead of Option<PoolSlot>. When pool
     is empty, the future parks on a FIFO waiter queue. PoolSlot::drop
     wakes the oldest waiter. No more malloc fallback path. The 512 MB
     pool ceiling is a TRUE hard cap on bounce RSS.

  2. Per-page volatile write_volatile in pool init replaces write_bytes
     to prevent compiler/LLVM elision. Combined with the worker thread's
     sched_setaffinity pinning (which runs before pool init), this
     guarantees Linux first-touch places pool pages on the worker's
     local NUMA node — no mbind needed.

  3. Metric renamed: exhaust_fallbacks → backpressure_waits. Counts
     parks instead of mallocs. Same semantic intent (saturation signal),
     different mechanism.

==============================================================================
What's now eliminated as a worry
==============================================================================

  - Pool exhaustion hidden by malloc fallback: gone. Async backpressure
    parks futures; throughput drops gracefully if oversubscribed, RSS
    stays flat. Metric exposes the park count for tuning.

  - Multi-socket NUMA wrong-node placement: handled by first-touch +
    pinned worker thread. Pre-fault is now bulletproof against compiler
    elision so pages actually get committed (and therefore land on the
    local node).

  - Recovery at multi-thousand density: empirically validated. 1025
    devices recovered in 120s via systemd auto-restart, all sampled
    devices pass CRC32C verify.

  - SLOT_SIZE coupling: compile-time assert prevents drift from
    IO_BUF_BYTES.

==============================================================================
What's still uncharacterized
==============================================================================

  - Multi-socket NUMA on actual production-class hardware. Single-socket
    homelab makes the NUMA-correctness claim true-by-construction but
    untestable.

  - Hour-plus sustained load. Burst tests up to 30 s only.

  - Pool exhaustion under deliberate adversarial workload (e.g., 4096+
    concurrent S3-await holders). Untested because synthetic exhaustion
    needs S3-side latency injection.
